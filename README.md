# COMMAND GRID — 統合戦線

軍事記号をモチーフにした、初心者向け同時命令型カードゲームです。Python / NiceGUIで動作し、1人用演習とオンライン1対1対戦の両方を遊べます。

## 遊べる内容

- 3戦線・9ラウンドの通常対戦と完全な勝敗判定
- 1人用の初心者演習（複数戦線へ柔軟に対応する決定論的AI）
- カジュアル / ランクのオンライン待ち合わせ
- 6文字の合言葉によるフレンド対戦
- お互いの命令を隠したまま送信し、両者が揃った時だけ同時解決
- 一時切断からの再接続、待機切れの自動整理、退出時の不戦勝・不戦敗
- 結果の重複記録防止
- 制圧・支援・偵察・補給・機甲ボーナス
- カード収集、最大12枚のデッキ編成、大隊・旅団・師団の編制表示
- 勝利は未所持カード1枚＋記号最大12種類、引き分けは記号最大3種類、敗北は記号最大1種類
- 201種類の記号図鑑と、解放済み記号のアカウントアイコン設定
- 勝ち方から命令・支援・補給・偵察までを一手ずつ学ぶ9章の基礎チュートリアル
- 全18種それぞれの5章訓練（最終章は3戦線の実戦配備）と、修了で受け取れる公式おすすめデッキ
- 公式デッキ内の未所持カード名表示と、未所持枠を空白にした安全なデッキ適用
- 基本18枚収集後に開く、全201記号カード・24枚デッキ・12ターンの本格シミュレーション
- PC用の広いグリッドUIと、スマホ用の固定下部ナビ・横スワイプ盤面
- アカウント登録・ログインと、SQLite / PostgreSQLによる進行状況の永続保存
- 戦績、勝率、任務点、最近の対戦履歴
- 初心者説明、確認画面、ログ、高コントラスト、文字サイズなどの永続設定

カードの兵科は「仕事」、大隊・旅団・師団は「表示する規模」です。編制規模だけでカードが強くなることはありません。

## ローカル起動

Python 3.12以降を用意し、仮想環境内で実行します。

```bash
pip install -r requirements.txt
python main.py
```

ブラウザで `http://localhost:8080` を開きます。オンライン対戦の確認は、通常ウィンドウとシークレットウィンドウなど、別々のブラウザセッションで行えます。

## アカウントとセーブ

登録しなくてもゲストとして遊べますが、端末やブラウザを変えて続きを遊ぶ場合はアカウントを作成してください。

1. 画面右上のアイコン、またはメニューの「アカウント」を開きます。
2. 初回は「新規登録」でユーザー名・表示名・パスワードを入力します。ユーザー名は半角英数字と `.` `_` `-` を使った3〜24文字、パスワードは8文字以上です。
3. 「アカウントを作成」を押すと、それまでのゲスト進行状況もアカウントへ保存されます。
4. 別のブラウザや端末では「ログイン」に同じユーザー名とパスワードを入力すると、保存した進行状況を読み込めます。

ログイン後は、カード・記号・デッキ・戦績・設定・チュートリアル進捗がプレイ中に自動保存されます。ログアウトしてもアカウントの保存データは削除されません。

### ローカルではSQLiteへ保存

`DATABASE_URL` を設定せずに `python main.py` を起動すると、プロジェクト直下の `command_grid_accounts.sqlite3` が自動的に作られます。特別なデータベース設定は必要ありません。

- このファイルがローカル環境のアカウントと進行状況の本体です。
- ファイルを削除すると登録データも失われるため、必要なら別の場所へバックアップしてください。
- SQLiteファイルはGitへアップロードされません。
- ローカルSQLiteのアカウントは、Renderのアカウントへ自動転送されません。両者は別の保存先です。

## Render

リポジトリ直下の `render.yaml` をBlueprintとして読み込むと、Webサービス `command-grid` とPostgreSQLデータベース `command-grid-db` が一緒に作成されます。どちらもSingaporeリージョンに置かれ、Webサービスの `DATABASE_URL` はデータベースの接続先へ自動設定されます。接続文字列やパスワードを手作業でコピーする必要はありません。

- Build Command: `pip install -r requirements.txt`
- Start Command: `python main.py`
- Health Check Path: `/healthz`
- Database: `command-grid-db`（PostgreSQL / 初期設定はFree）

初回はRender DashboardでこのリポジトリをBlueprintとして登録します。すでにBlueprintを作成済みの場合は、最新の `render.yaml` を同期し、`command-grid-db` と `DATABASE_URL` が追加されたことを確認してください。登録ユーザーの進行状況はPostgreSQLへ保存されるため、Webサービスのスリープ、再起動、再デプロイだけでは消えません。

> **無料データベースは長期保存用ではありません。** RenderのFree PostgreSQLは作成から30日で期限切れになり、期限切れ後はアクセスできなくなります。その後14日間は有料プランへアップグレードできますが、猶予期間を過ぎるとデータベースと保存データが削除されます。友人へ公開する前、または30日の期限より前に、有料のPostgreSQLプランへアップグレードすることをおすすめします。詳しくは[Render公式の無料枠説明](https://render.com/docs/free)を確認してください。

オンラインの待機列と進行中の対戦は、現在も1つのWebプロセス内で共有します。そのためインスタンス数は1のままにしてください。進行中の対戦は再起動時に終了しますが、ログイン済みユーザーのカード、デッキ、戦績、設定、チュートリアル進捗はデータベースから再び読み込めます。未登録のゲスト進行状況はPostgreSQLには保存されません。

データベース接続の定義は[Render Blueprint YAML公式仕様](https://render.com/docs/blueprint-spec)に沿っています。
